# 凡人问道录 · ImmortalGame

一个纯原生 HTML/JS 的文字修仙放置游戏，从苍梧门杂役一路修到筑基、结丹。无需任何构建工具与依赖，克隆后直接用浏览器打开 `index.html` 即可游玩。

## 特色

- **原著剧情线**：苍梧门 → 玄机子 → 血月试炼 → 青梧谷 → 云京皇宫 → 碎星海
- **数据 / 逻辑 / 表现三层分离**：`data/`（纯数据）+ `js/`（GAME 命名空间模块）+ `index.html`（表现层）
- **修炼系统**：练气十二层 → 筑基 → 结丹；资质、灵根、心境、敛息、青木功层数
- **破境筹备**：突破成功率不是黑箱——丹药底子 + 灵脉灵气 + 玄傀护法 + 心境 + 《三转归元功》
  逐项摊开（面板与掷骰读同一份推演），每项都对着一份代价：灵石租金、玄傀气血、丹药与心境积累。
  失败反噬与身陨率同样明码，玩家是在调概率，而不是赌概率
- **功法**：青冥剑诀（护盾 + 破甲）、三转归元功（散功重修，永久成长）
- **承露瓶**：绿液催熟灵药（百年/千年）、炼丹（含抗药性机制 1-5 全效 / 6-10 减半 / 11+ 无效）
- **玩法系统**：坊市（含"结丹老怪觊觎"风险值）、黑市轮换、傀儡工坊、灵兽园、妖虫养成、师承红颜羁绊、承露瓶风险泄露
- **副本试炼**：黑石矿洞 / 万妖窟外层 / 魔修弃营（分阶刷装备）、幽冥教赤玉蛛巢穴（两阶段 Boss）
- **多结局**：按筑基期抉择分出 5 种结局（飞升 / 结丹 / 双修 / 独修 / 魔修）
- **地图成长**：境界锁定的地图节点提前展示（可望不可及的期待感），遭遇战按玩家修为匹配怪物池

## 玩法循环

游戏以"半年/月"为单位推进回合，核心循环如下：

1. **洞府经营**：闭关打坐攒修为（半年 +1）、承露瓶绿液催熟灵药（百年/千年灵药、灵木幼苗、玄冰花、龙鳞果）
   → 修为圆满后先看**破境筹备**：灵脉、护法、丹药能凑到几成，再决定此刻冲还是再等等
2. **开炉炼丹**：催熟与采药获得灵药 → 炼制筑基丹/回春丹等丹药；同一丹药越吃越抗药（1-5 颗全效 → 6-10 颗减半 → 11+ 颗无效），逼迫玩家规划长期服药节奏
3. **坊市与黑市**：卖药换灵石，但"药香泄露"与"觊觎风险值"会累积——风险太高，离开坊市时可能被结丹老怪拦路；黑市每 3 个月轮换一次货源
4. **外出历练**：1~3 个月的野外行程，遭遇战怪物按玩家当前修为从怪物池匹配（低修为遇不到金丹怪，反之亦然）；地图上境界不足的节点（如云京城、碎星海）会提前展示但无法进入
5. **副本试炼**：三档分阶副本（黑石矿洞 / 万妖窟外层 / 魔修弃营）刷材料与装备过渡，幽冥教赤玉蛛巢穴为两阶段 Boss 战（先破 4 名血仆削弱 Boss 气场，再面对 30% 狂暴 + 80% 法术抗性的本体）
6. **养成线**：傀儡工坊（矿洞材料造傀儡）、灵兽园、妖虫养成、师承红颜羁绊（李玄尘 / 凌清沅 / 柳蔓儿 / 温巧兮，影响心境与结局走向）

## 剧情脉络

忠于原著早期主线的关键节点链：

```
苍梧门(杂役) → 玄机子收养/夺舍危机 → 玄机世家遗府 → 血月试炼(夺筑基丹)
  → 青梧谷拜师(李玄尘) → 青木功/承露瓶 → 云京皇宫(幽冥教·赤玉蛛)
  → 结丹之争 → 碎星海(当前版本终点)
```

- **练气期**：出身选择（影响初始属性与灵根）、苍梧门到玄机世家的生存线、血月试炼的生死抉择
- **筑基期**：核心玩法全面展开——洞府、炼丹、坊市、副本、羁绊；三种抉择倾向（正道 / 双修 / 入魔）积累因果值
- **结局**（5 种，由筑基期抉择决定）：飞升问道 / 结丹留世 / 道侣双修 / 独修百年 / 堕入魔道

## 运行

直接双击 `index.html`，或：

```bash
cd ImmortalGame
python -m http.server 8080
# 浏览器访问 http://localhost:8080
```

## 测试

基于 Node 的冒烟测试（`vm` 沙盒 + 确定性随机）：

```bash
for f in test/smoke*.js; do node "$f"; done
```

## 界面（功能归类）

页签不按「系统」排，按**你现在想干什么**排：

| 一级 | 回答的问题 | 收进去的页签 |
|---|---|---|
| 修行 | 想把时间换成修为 | 洞府 · 丹炉 · 功法 |
| 游历 | 想出门换资源 | 大地图 · 市集 · 秘境 · 副本/试炼 |
| 身家 | 想整理已有的东西 | 储物袋 · 灵宠/傀儡 · 图志/道碑 |
| 宗门 | 想处理门派事务 | 门派 |

- 同屏只露当前组的 3~4 个页签。11 个长名按钮平铺时，390px 的手机上会被挤成一字竖排（`副本/试炼` 竖着读），这是改分组最直接的原因。
- 一级导航记住每组上一次停留的页签，点「修行」不会永远跳回洞府第一项。
- 进不去的页签**显式锁定**（虚线边 + 压暗 + title），而不是点了没反应：丹炉在练气三层前由玄机子解锁。
- 修为不再只有 `0 / 20` 两个数字，顶栏有一条进度条（`#exp-fill`，蓝→金渐变，满则转亮）。
- 契约由 `test/smoke_nav.js` 看住：页签漏归类、HTML 标注与 `groupOf()` 不一致、按钮 id 与页签 key 对不上（历史上副本页正是因此永远不高亮），都会直接变红。

## 时间系统（年月账簿）

时间不是背景数字，是一笔会花完的预算。`js/time.js` 是时间相关推演的唯一出口：

- **预算**：顶栏直接显示「100岁 · 余84年」，随境界、延寿丹、折寿实时变；余 10 年转黄、余 5 年转红。
- **分档闭关**：静修（1 周天）/ 闭关（3）/ 苦修（6）/ 长关（12）。修为严格按「一周天 +1」折算，长关额外养**心境**（每 4 月 +1）——心境每 10 点给破境 +2%，于是「花几个月」变成一种真实的资源分配。
- **药圃**（`js/plot.js`）：时间不只是花掉的，也是长在土里的。三垄地，把一株【百年灵药】移栽下去，每月长 3 年份（灵峰 ×1.5/×2），满 1000 年收【千年灵药】——不用绿液也能攒出筑基丹与延寿丹的主药。代价是年复一年的寿元；灵田设施收成时多给几株。
- **两条产药路**：绿液催熟（快、稀缺）对药圃慢养（慢、免费）。药圃不解决「还能活几年」，只解决「材料从哪来」。
- **地雷守卫**：寿元撑不到出关、尸虫丸/阴毒会在关内毒发时，直接拦下并说明原因（不弹窗、不灰按钮不说理由）。

## 坐化（寿元尽）

`js/mortality.js` 管"死"这件事。寿元归零不是删档加一行日志，而是**这一世结束**：

- **一世账目**：坐化时弹一页账——在世几年、止步哪一层、斩妖几头、炼丹几炉、药圃还剩几垄、故人几位、未了之事差多少。数字全部来自 `p.stats` 与 `p.plots`，`reckon()` 是纯函数，UI 与结算读同一份。
- **判词**：按境界、杀孽、心境、是否种过药给五档不同的墓志铭，不是一句"你死了"。
- **遗书**：三选一，写给后来者。
- **传承（只传带不走的）**：地里还没熟的灵药会在无人看管的年月里再长 10 年，新角色开局时接着种——"他没等到，你等到了"。**灵石一分不传**，否则死亡会变成刷资源的捷径；领过即焚，防止反复领。
- **弥留**：余寿 ≤3 年时目标卡改口（"寿元仅余 N 年——闭关前先算好，别把自己关死在蒲团上"），提前给压力，而不是突然一行红字。

气血耗尽等其他死法不走坐化（它们没有"一世"可交代），仍走原来的道陨提示。

## 章节扉页（美术）

`assets/ch/` 存水墨扉页，数据层 `MAP.chapters[].art` 指路，`renderMap` 里**有 art 才画**——缺图不占位、不裂版。

尺寸用 `clamp(76px, 12vh, 108px)`（窄屏 64~84px），只占一条，不与被删掉的大横幅一样抢版面。

## 关于"去原著化"

本项目早期版本曾参考仙侠题材通俗作品的世界观框架。为降低版权风险，已对全部独创性专有名词（人物、门派、地名、功法、法宝、事件）做**系统性改名**，现版本为**架空原创设定**；仅保留修仙题材通用词汇（练气 / 筑基 / 结丹 / 灵石 / 符宝 / 傀儡 / 心境 等）。

批量改名采用「长词优先」的程序化替换，代码内部 id 与逻辑不动、只改展示文本，共替换 978 处、涉及 47 个文件；替换后全部冒烟测试与基线一致，无新增失败项。
